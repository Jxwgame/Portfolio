Header.tsx — navbar plan

Two navbars,
one shell

ตอนนี้ทั้งเว็บใช้ Header.tsx ตัวเดียว แต่จริง ๆ แล้วมันต้องรับมือกับบริบทที่ต่างกันสองแบบ คือ “อยู่ตรงไหนของหน้าที่กำลังเลื่อนอ่าน” กับ “อยู่หน้าไหนของเว็บ” — แผนนี้แยกพฤติกรรม 2 โหมดออกจากกันให้ชัด โดยยังใช้เปลือกแคปซูลเดียวกัน

01 สถานะปัจจุบัน

หน้าแรก (/) กับหน้าย่อย (/about, /work, /contact) ใช้ navbar หน้าตาเดียวกันทุกพิกเซล รวมถึง เส้น segment ใต้ไอคอนที่ค่อย ๆ ไล่เติมสี ตามลำดับเมนู — ตัวเส้นนี้ถูกออกแบบมาให้สื่อ “สกอลล์ผ่านมาไกลแค่ไหนแล้ว” (จาก IntersectionObserver บนหน้าแรก) แต่พอไปอยู่บนหน้าย่อยที่สลับกันด้วยการ คลิกลิงก์ ไม่ใช่การเลื่อน มันก็ยังเติมสีเหมือนเดิมทั้งที่ไม่มี “ระยะทาง” ให้สื่อความหมายจริง ๆ

02 สองโหมดที่ต้องแยก

ลองเลื่อน/กดปุ่มในกล่องด้านล่าง — ฝั่งซ้ายจำลองพฤติกรรมหน้าแรก ฝั่งขวาจำลองพฤติกรรมหน้าย่อย ทั้งคู่ใช้แคปซูลแก้วมืดแบบเดียวกัน ต่างกันแค่ตัวชี้ตำแหน่ง (indicator) และแหล่งที่มาของสถานะ active

03 สรุปความต่างเชิงพฤติกรรม

คุณสมบัติโหมด A — หน้าแรกโหมด B — หน้าย่อย
ลิงก์เมนู item.hash (#about) item.href (/about)
ที่มาของ active IntersectionObserver จับ section ที่เห็นอยู่ เทียบ usePathname() ตรง ๆ
Indicator เส้น segment ไล่เติมสีทีละช่วง (rail-fill) พื้นหลังวงรีเลื่อนไปเกาะไอเทมที่ active (tab-pill)
จังหวะเปลี่ยน ต่อเนื่องตามอัตราสกอลล์ ดีเลย์เหลื่อมทีละ segment ทันทีเมื่อคลิก/เปลี่ยนหน้า (~300ms ease)
ความหมายที่สื่อ “มาไกลแค่ไหนแล้วในหน้านี้” “ตอนนี้อยู่หน้าไหนของเว็บ”
เปลือกที่ใช้ร่วมกัน แคปซูลแก้วมืด, Brand, ปุ่ม hamburger, เมนูมือถือแบบ full-screen — เหมือนเดิมทุกอย่าง ไม่แยกดีไซน์

04 แนวทาง implement

  • แตกจาก isHome เดิม — Header.tsx รู้อยู่แล้วว่าอยู่หน้าแรกหรือไม่ ใช้ตัวแปรเดิมนี้เลือก render <RailIndicator/> หรือ <TabPillIndicator/> แทนโค้ด segment เดิมที่ฝังไว้ตายตัว
  • Tab pill ไม่ต้องพึ่ง library ใหม่ — เพราะ Header อยู่ใน root layout.tsx จึงไม่ remount ระหว่างเปลี่ยนหน้าแบบ client-side navigation คำนวณตำแหน่ง/ความกว้างของไอเทม active ด้วย getBoundingClientRect() แล้ว transform: translateX() ก็สไลด์ข้ามหน้าได้เลย โดยไม่ต้องเพิ่ม framer-motion
  • เปลือกแคปซูลและเมนูมือถือคงเดิมทั้งหมด — ของเดิมออกแบบมาดีอยู่แล้ว (glass + blur, full-screen overlay ตอนมือถือ) เปลี่ยนแค่ตัว indicator ใต้ไอคอนภายในแคปซูล ไม่แตะโครงสร้างอื่น
  • หน้า case study (/work/[slug]) ยังนับเป็น “หน้าย่อย” (โหมด B) เพราะ active เมนูคือ “Experience” เทียบจาก route เหมือนกัน — ไม่ต้องเพิ่มโหมดที่ 3
